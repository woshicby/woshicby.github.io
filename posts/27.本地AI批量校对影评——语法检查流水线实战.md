给网站里的影评做了一次语法体检,记录一下这套「本地 AI 初筛 + 人工审阅」流水线,以及过程中踩的坑。

# 📋 任务背景

网站书影音游页面攒了 **812 条电影记录**,其中 **86 条有影评内容**(约 1 万字)。想检查所有影评的语法错误——包括但不限于「的地得」用错、错别字、病句、标点误用。

原则:**检查工作交给本地 AI**,我只负责审核它的产出,最后修改决定权在用户手里。

# 🔧 方案设计

## 1. 选模型

用 LM Studio 里的 **qwen3.6-27b**(本地文本模型,隐私零成本)。86 条影评按每批 8 条分 11 批,让模型输出结构化 JSON 错误清单。

## 2. Prompt 设计

System prompt 明确四类错误:「的地得」/错别字/病句/标点,并且:

- 只报**确定的**错误,不确定的不报
- 每条输出:编号、标题、原文片段、错误类型、修改建议
- 最终输出 JSON(`{"errors": [...]}`),不要其他文字

## 3. 结果处理

模型产出 → 脚本解析 → 汇总成 **md 审阅表**(每部影评一节:完整原文 + 错误清单表格 + 空白「决定」列)→ 用户逐条审阅打勾。

# 🕳️ 踩的坑

## 坑 1:max_tokens 太小 → 思考模型 content 全空

第一批跑完发现**所有批次 JSON 解析失败,返回内容为空字符串**。排查:qwen3.6-27b 是 reasoning 模型,单次任务思考就吃了 **6000+ tokens**,`max_tokens=2048` 全被思考过程耗尽,`content` 字段直接空。

> 这和我之前修过的 Hermes 标题生成 bug 是**同一个根因**:reasoning 模型 + 小 max_tokens = 静默失败。

**解决**:`max_tokens` 提到 **8192**,实测正常返回。

## 坑 2:AI 建议不等于正确

75 处疑似问题里混了不少「AI 不懂人类修辞」的误报,举几个用户一眼识破的:

| 原文 | AI 建议 | 用户裁决 |
|---|---|---|
| 台词:请坐和放宽 | 请坐好并放宽心 | **不改**——故意的微软机翻梗 |
| 翻译很难蚌 | 翻译很难绷 | **不改**——蚌埠住了的谐音梗 |
| 巨大化敌短 | 巨大化敌人 | **不改**——刀剑乱舞里「敌短刀」的专业词 |
| 任天堂的护城海太宽了 | 任天堂的护城河太宽了 | **不改**——故意造词,表达「护城河宽得像海」 |
| 主角雀食丑(但人影片也说主角丑啊 | 但影片也说主角丑啊 | **不改**——去掉「人」就失去口语风格了 |

结论:**AI 只能当「初筛器」,不能当「裁判」**。它擅长抓「的地得」「错别字」这类硬错误,但遇到玩梗、口语、专业术语、个人风格表达,经常会"好心办坏事"。

## 坑 3:原文片段匹配失败

模型输出的「原文片段」经常和实际文本**对不上**(标点、换行差异),直接字符串替换会失败。处理:

- 优先用模型给的片段做精确替换
- 失败的条目转人工:打印完整原文,用**换行感知**的精确片段重试
- 最后 6 条是「换行处加标点」类,人工定位后全部命中

## 坑 4:断点续跑

任务中途被中断过一次(最后一批没跑完)。脚本设计成**结果按批次落盘** + 重启时跳过已完成批次,重跑只补缺失批次,不浪费已经跑完的 10 批。

# 📊 最终数据

- 检查 86 条影评 / 约 1 万字
- AI 初筛出 **75 处疑似问题**(错别字 26 / 标点 22 / 的地得 15 / 病句 12)
- 涉及 43 部影评
- 用户审阅后:跳过 7 处(玩梗/口语/专业词),其余采纳
- 最终修改 **40 部影评 / 90 处**

# 💡 经验沉淀

1. **「AI 初筛 + 人工审阅」是文本质检的黄金组合**:AI 负责体力活(逐条扫),人负责判断(哪些是真错、哪些是风格)。效率比纯人工高一个量级,准确性比纯 AI 高一整个维度。
2. **审阅表格式很重要**:每部影评显示完整原文 + 错误表格 + 空白「决定」列,用户逐条打勾零门槛。
3. **reasoning 模型的 max_tokens 要给足**:思考吃掉的 token 远超直觉,宁大勿小,否则静默失败比报错更坑。
4. **AI 建议要保留原始语境**:让模型输出「原文片段 + 修改建议」而不是只输出「改完的整句」,这样人工审阅和自动替换都能精确对位。
5. **本地模型做这种隐私任务很合适**:影评是个人内容,全程不出本机,零成本。
